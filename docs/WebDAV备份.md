# 备份与云同步

入口：设置 → 备份与云同步。界面分为导入与导出、本地备份与恢复、WebDAV 云同步。

## 本地备份

点击“立即备份”生成 SQLite 在线快照，包含 WAL 中已提交的战绩。生成后列表和数量自动更新，可重命名、导出 ZIP、删除或恢复。导入、重命名、删除和云端下载后同样自动更新；设置页可见时每 5 秒检查本机备份列表，后台自动备份也会显示。导入只接受 Evo 导出的 ZIP（兼容前一版 WebDAV ZIP），先校验，导入本身不覆盖战绩。导出文件可另存到移动硬盘等位置。点击“备份文件夹”可直接在资源管理器查看本地备份。

本地自动备份默认每 24 小时、保留 10 份；可关闭，或选择 1/6/12/24 小时、3/7 天，保留 5/10/20/50 份。Evo 运行时每分钟检查，游戏运行时延后。保留数量只清理自动备份；手动备份、导入、云端下载和恢复前备份由用户手动删除。备份位于数据目录的 data/backups，随“更改数据位置”一起搬迁。

## WebDAV 配置

直接填写 WebDAV 服务器目录地址，无需选择服务商。已有配置的地址、账号和密码继续保留。填写账号、密码或应用专用密码、远程根目录（默认 evo-sync）和同步配置名（默认 default），点击“保存配置”在原位置完成保存，按钮旁显示结果，不刷新页面或跳回模块顶部；保存后可直接测试连接。两台设备填写相同的服务器、账号、根目录和配置名，才能访问同一份云端版本。配置名可区分多份独立数据。

连接信息由 Windows DPAPI 加密保存在本机 data/webdav_credentials.bin；不会回传密码到网页，也不会放进备份。换电脑、Windows 用户或重装系统后需重新填写。地址或账号更改时必须重新输入密码。坚果云使用第三方应用密码。建议 HTTPS；HTTP 会明文传输认证信息和数据。ZIP 本身未加密，其保护依赖服务器权限。

两个云端自动开关默认关闭：每天自动备份（本地自然日每天成功一次）和数据变化后自动上传（每分钟检查战绩与白名单设置的变化）。两者都只在 Evo 运行时工作，游戏运行时延后；失败后每小时重试。关闭窗口但保留托盘仍可运行，完全退出则不执行。自动上传不会自动下载。

旧 WebDAV 备份版的连接仍可用于原来的每日上传。重新保存配置后启用新的根目录/配置名协议；旧云端 ZIP 可下载后通过本地“导入备份”使用。旧文件不删除。

## 换设备使用

HTTPS 连接使用系统证书库，并补充随程序分发的 certifi 公共根证书库，保留证书、域名校验及 Python 发行版的证书拒绝策略。完整解压程序并保留 _internal 文件夹；升级程序同时更新内置证书库。

若仍报 HTTPS 错误，提示会包含具体原因和校验码：9/10 请先检查 Windows 日期、时间和时区；20/21 请检查服务器中间证书和网络代理；62/64 请使用证书对应的域名。自建服务器或企业代理的私有 CA 需按管理员提供的可信流程配置系统信任。不会自动信任服务器提供的证书或跳过校验。

1. 在原设备退出 Apex，点击“上传到云端”，等待成功。
2. 在新设备填写相同的 WebDAV 配置，点击“从云端下载”。
3. 下载经过哈希、SQLite 和结构校验后，自动出现在本地列表，在对应 cloud 备份点击“恢复”。
4. 确认对局数、账号数和备份时间，确认后 Evo 自动重启恢复。源码运行时需手动从托盘退出并重新启动。
5. 检查战绩无误后，可重新保存云端配置或手动上传，恢复自动上传。恢复后默认暂停自动上传，避免旧快照未经确认即覆盖云端。

数据库保留 player_names 中的账号编号、已确认状态、合并过的名字，以及账号展示名。相同玩家名、战队标签变化、空格或 1/l/I 识别变体继续归入同一账号；真正改名仍需按 Evo 提示确认。备份不代替 Steam/EA 登录，也不保证不同设备的截图/OCR 环境完全相同。

## 冲突与恢复保护

另一台电脑仅运行 Evo 不会占用云端目录。上传时短暂持有写入锁，下载不获取写锁，也不创建远端目录；测试连接同样只读取远端。原设备上传完成后，即使继续运行，新设备也可下载该快照。

HTTP 409 表示服务器拒绝了当前路径操作，不等同于 Evo 的写锁提示。错误中会说明是在读取、写入还是创建目录时失败；请核对服务器目录、远程根目录、同步配置名，以及同名位置是否为文件。对目录探测返回 409 的服务，上传会逐级检查并创建目录；实际建目录、上传或下载返回 409 时仍明确报错。测试连接会区分“已找到快照”与“连接成功但尚无快照”，不会为了测试创建空目录。

云端保留不可变 ZIP 快照，以 latest.json 表示当前版本。上传先用 MKCOL 原子创建 evo-write-lock 空文件夹，成功后才检查版本并写入，完成或失败后释放锁。服务器需遵守已有目录返回 405 的 WebDAV 语义，所有参与同步的设备应升级到此版。

有强 ETag 时继续使用 If-Match 条件更新；缺少 ETag、弱 ETag 或未加引号时，使用版本文件的 SHA-256 校验，并在提交前再次检查云端版本。下载无需强 ETag，仍会校验 ZIP 哈希和数据库结构。发现本机尚未同步的云端版本，会停止上传并提示先下载，或由用户确认用本机覆盖。确认后若云端又发生变化，仍会停止覆盖。云端历史快照暂不自动清理。

若上传时断电或断网，写入锁可能残留。程序不会按超时抢锁，避免慢设备恢复后误覆盖。只有确认所有设备的 Evo 均已退出后，才可在网盘的“服务器目录/远程根目录/同步配置名/”下删除空文件夹 evo-write-lock，再重新打开 Evo；不要删除快照或 latest.json。

这是整库快照传输，不自动合并两台设备各自新增的对局。轮流使用时，先上传旧设备，再在新设备下载恢复。两边都有新记录时，先分别导出留存再选择保留哪一份。

恢复会替换全部账号的战绩和白名单设置。程序先暂停记录，主进程重新启动并获得单实例锁后，在开启任何数据库连接前执行恢复；先自动生成 rollback 备份，保存原文件和设置作为撤销数据，再提交替换。失败回退，执行中意外退出会在下次启动先撤销未完成的事务。待重启期间拒绝页面写操作和搬家。游戏运行时不允许恢复。

导入/下载 ZIP 最大 256 MB，解压数据库最大 1 GB；仅提取固定文件名，拒绝额外路径、重复成员、损坏哈希、新于当前程序的数据库版本、视图/触发器和残缺表结构。升级及验证均在临时副本上进行。

## 备份范围与验证

ZIP 含 data/evo.db、settings.json、manifest.json 和恢复说明。包含全部账号的战绩、自己与队友的游戏名和账号对应关系。常规设置白名单为主题、侧边栏秒数、提示音开关/声音包/音量、游戏语言/比例、展示名、截图保留开关。不含截图、录像、自定义音频、日志、CDK、匿名统计编号或任何登录凭证；数据库中的媒体关联仍保留，缺少媒体文件时无法打开。

测试使用隔离的临时数据与本机 WebDAV 接收端，覆盖认证、WAL 快照、日调度/变化检测、失败重试、版本冲突、强/弱/缺失/未加引号 ETag、远端写锁互斥、提交前复查、下载校验、保留数量、账号连续性、恢复失败回退与中断撤销。Windows 打包程序验证真实后台调度、下载、自动重启恢复和恢复前备份。未连接个人网盘，也未进行真实 Apex 对局测试。
