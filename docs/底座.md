# 底座：截屏、库、窗口、托盘、打包、安装、发布

打包、发布、安装、改托盘或窗口时读这份。日常改模型、改页面用不到。

## 截屏和识别用的库

- 截屏：`dxcam`（DXGI）为首选，备选 `mss`（GDI，零依赖）。两者在全屏下都可用，dxcam 平均 4.6 ms、mss 28 ms。WGC（`windows-capture`）为保持轻量暂不采用
  - dxcam 0.3 要用 `processor_backend="numpy"`（默认依赖 OpenCV）；mss 10.2 用 `mss.MSS()`（旧写法 `mss.mss()` 已弃用）
  - **dxcam 建不起来时**（`code/capture.py`，2026-11-03 用户决定，记录程序和测试工具共用）：报 `DXGI_ERROR_UNSUPPORTED`（双显卡的笔记本上 Evo 跑在独显上，原因见 docs/识别经验.md）→ 在 Windows 图形设置里把 Evo.exe 设成「节能」（注册表 `HKCU\Software\Microsoft\DirectX\UserGpuPreferences`，值名是 exe 的完整路径，`GpuPreference=1;`，同一个值里别的设置照旧；和玩家自己在 设置 → 系统 → 屏幕 → 显示卡 里设一样，不用管理员权限）。新开的进程才生效：记录子进程抛出 `capture.NeedRestart`，托盘程序马上重开（只马上重开一次，再要就按出错等 60 秒）；测试工具改它自己，下次打开生效。已经是「节能」还不行、写不进去、别的原因、用源码运行（不改 python.exe）→ 改用 mss 截主显示器（每张约 21 毫秒截屏 + 3 毫秒转 BGR；测试工具不带 OpenCV，转 BGR 约 25 毫秒），对游戏帧数的影响没实测过，所以只在 dxcam 用不了时用。日志里"屏幕: …（截屏：dxcam / mss）"看得出用的哪种；建截屏对象在建这次的截图文件夹之前（以前建不起来时每 60 秒多一个空文件夹）。mss 纯 Python，安装包多约 0.2 MB
  - CPU：桌面上实测，dxcam 截一张只要约 4 毫秒，但之后进程里约 15 个线程（很可能是显卡驱动的）空转约 0.1 秒，每张合计约 1.4 秒 CPU；mss 每张约 0.01 秒。截图频率对内存几乎没有影响（每 1 秒和每 0.3 秒都是约 126–136 MB）。游戏里实测（2560×1440，对局中每 0.3 秒一张）：记录子进程 CPU 平均 14–21% 个核，内存约 200–220 MB，比桌面上低得多；帧数影响还没测
- 图像处理：`opencv-python-headless`（RapidOCR 的依赖，无图形界面版；不要再装 `opencv-python`，两者会冲突）、`numpy`
- OCR（引擎）：RapidOCR 3.10 + onnxruntime 1.31。模型（PP-OCRv6 small 检测 / 识别）内置在安装包里；代码中直接指定 `model_path`，不会触发联网下载。单线程，关闭方向判断（`use_cls`）
- 各库的内存：dxcam 49 MB（含 DirectX 组件）、onnxruntime 35 MB（第一次建引擎时才加载，之后一直在）、cv2 17 MB、numpy 13 MB；识别模型约 40 MB，可以释放（`ocr.LazyEngine`：用到才加载，闲置 2 分钟释放）
- 优先级和省电限速：记录子进程一直是"低于正常"优先级（`process_info.set_low_priority`）。**读结算画面、大厅时不让 Windows 降频**（`process_info.set_full_speed` + `live_collect.FullSpeed`，2026-10-27 用户决定）：进入淘汰画面、冠军横幅、"返回大厅"按钮、总结页、经验值页、大厅时告诉 Windows 别限速（`SetProcessInformation` 的 `ProcessPowerThrottling`，ExecutionSpeed 设成不限速），离开 10 秒后、或对局中认出自己的传奇时交还给 Windows 决定。原因：两位笔记本玩家（1diot、0010）的识别比台式机慢 10–15 倍，诊断工具（有窗口）只慢 2 倍左右，怀疑 Windows 给没有窗口的记录子进程开了省电限速（EcoQoS：降频、挪到小核）；台式机上设不设都一样，复现不了。优先级、线程数不变，同样的活干得快；对局中照旧。日志"本次记录"一行的"识别 N 次（平均每次 x 秒）"用来比较快慢（用户的台式机不开游戏时约 0.03 秒：读队友 14 次共 0.45 秒）；几份日志里各步用时用 `python tools/log_speed.py 日志…` 比较

## 窗口、面板、托盘

- 面板：Flask + 模板 + 纯 HTML/CSS（少量 JS），不用 React、Node.js。运行时不加载任何网络资源。端口 5000–5019（Chromium 内核会拒绝 5060 等"不安全端口"）
- 窗口：`pywebview`（BSD）+ Windows 自带的 WebView2（`app_window.py`）。去掉系统边框，自定义深色标题栏（图标、EVO、最小化 / 最大化 / 关闭）；拖动和改大小交给 Windows 原生处理（在标题栏 / 边缘按下时发 WM_NCLBUTTONDOWN）。面板网页靠 User-Agent 里的 `EvoApp/` 知道自己在窗口里。窗口打开时独占约 130 MB（Python 52 MB + WebView2 约 80 MB），关掉全部还回去。要像 Outplayed、Blitz 那样的软件窗口，不在浏览器里打开
  - WebView2 检查（`webview2.py`，0.3.4 起）：pywebview 找不到 WebView2 时不报错，悄悄改用 IE 内核，面板只剩一堆没排好的文字（2026-10-19 用户反馈）。所以窗口子进程打开前先查注册表（和 pywebview 的判断一样：版本 ≥ 86.0.622.0、.NET Framework ≥ 4.6.2）；没有就弹 Windows 自带的对话框问要不要装，点"是"运行 `_internal/webview2/MicrosoftEdgeWebview2Setup.exe /install`（微软的常青版引导程序，约 2 MB，带它自己的进度窗口，从微软下载一百多 MB），装好就开窗口；点"否"或没装上，托盘程序用浏览器打开面板，这次运行里不再问（用户自己装好了就照常开窗口）。`app_window.run` 再兜底：pywebview 要用的不是 `edgechromium` 就报错，托盘程序改用浏览器。2026-10-19 用 Globalping 从深圳、广州、南京测过微软的下载服务器（`go.microsoft.com`、`msedge.api.cdp.microsoft.com`、`msedge.sf.dl.delivery.mp.microsoft.com`）都能连上，约 1 秒；还没在真正缺 WebView2 的电脑上试过
  - 下载标记（`webview2.unblock`，0.4.1 起，2026-10-25 玩家反馈、用户决定）：用 Windows 自带的"全部解压缩"解开压缩包时，每个文件都带上"从网上下载的"标记（附加数据流 `Zone.Identifier`，SmartScreen 也是看它）。.NET Framework 不加载带这个标记的程序集，pythonnet 报 `Failed to resolve Python.Runtime.Loader.Initialize from …\Python.Runtime.dll`，窗口打不开、每次都用浏览器（用 7-Zip 等不传标记的解压软件、自己电脑上打包的不会这样，所以开发时没遇到）。所以打包版每次启动（`evo_app.main`）先删掉 `_internal` 里 `pythonnet`、`clr_loader`、`webview` 三个文件夹下 DLL 的标记（约 10 个文件，没有标记就跳过），去掉了几个、去不掉的（程序文件夹不能写入）都写进日志。一键更新、补丁包写的文件本来就没有标记。看日志：窗口打不开的原因里有这行报错、又没有"去掉了 … 个文件上'从网上下载的'标记"，就是这个问题；手动解决：退出 Evo，PowerShell 里 `Get-ChildItem '程序文件夹' -Recurse | Unblock-File`
  - 面板文件的类型写死（`panel_app.py`）：Flask 按 Windows 注册表判断文件类型，有的软件会把 .css 改成 text/plain，WebView2 和浏览器就不用这个样式表，症状和用了 IE 内核一样
  - 字体：数字和英文用 Chakra Petch（OFL 许可，woff2 文件放进项目），中文用系统自带的微软雅黑
  - **视频真全屏**（`WindowApi._set_fullscreen`，2026-11-21 用户问的：录像、看直播点全屏只铺满 Evo 窗口里那一块，不是整块显示器）：原因是 pywebview 不管 WebView2 的 `ContainsFullScreenElementChanged`。网页加载好以后挂上这个事件（只挂一次，在窗口线程里）：网页里的东西全屏时窗口撑满所在的整块显示器（盖住任务栏，Windows 11 的圆角先改直角），退出时回到原来的位置和大小，原来是最大化的回到最大化（工作区，不盖任务栏）；出错就算了，全屏照旧只铺满窗口。WebView2 里按 Esc 不一定退出全屏，`base.html` 里补了一句：全屏时按 Esc 就 `exitFullscreen`。用浏览器打开面板时浏览器自己会做，不受影响。11-21 用源码开真窗口试过（用 DevTools 协议带用户手势让视频全屏、模拟按 Esc）：普通窗口 → 全屏 2560 × 1440 → Esc 回到原样；最大化 → 全屏 → Esc 回到最大化 2560 × 1392；截整块屏幕看任务栏被盖住了。窗口不在前台时网页的全屏请求会被拦（点按钮时窗口一定在前台）
  - **启动画面**（`code/splash.py`，2026-11-22 用户要的：从托盘打开 Evo 时先黑 1–2 秒才出内容）：原因是窗口进程打开窗口以后，WebView2 要先启动自己的浏览器进程（约 0.35 秒），再加载、画出面板网页（约 0.2 秒），面板生成网页只要 40 毫秒，这段省不掉（11-21 用源码量：点打开后 0.8 秒窗口出来、1.35 秒网页画好；打包版、电脑忙时更久）。现在窗口一出来就是启动画面：和网页一样的标题栏（图标、EVO、三个按钮），中间 Evo 图标、一行小字「APEX 爱好者」和一条来回走的细蓝条（用户从几批样子里挑的：A 款"图标 + 细加载条"；字是 15 号：APEX 用 Cinzel、爱好者用思源宋体 ExtraLight，灰色；11-22 用户看了截图要放大、"家"改成"者"：图标 96 像素、字 20 像素（放大了两次））。用 WinForms 自己画（`app_window.run` 在 `before_show` 里盖上一块 PictureBox），不靠 WebView2；网页画好以后（`base.html` 在 `pywebviewready` 后等两帧）调 `WindowApi.page_shown` 拿掉，网页的标题栏正好接上；网页一直没调（出错页等）加载完 2 秒后拿掉，最多盖 15 秒。Windows 关了"动画效果"时蓝条不动
    - 颜色跟着面板主题：网页把选的主题（深色 / 浅色 / 跟随系统）告诉窗口（`remember_theme`，变了才写 `settings.json` 的 `window_theme`），下次打开时窗口底色和启动画面用它，"跟随系统"读注册表 `AppsUseLightTheme`。以前底色写死深色，浅色主题的人会先黑一下再变白
    - 字体：`assets/splash/` 里只含那几个字的小字体文件（合计约 5 KB，OFL，许可在旁边），`python tools/splash_fonts.py` 从 Google Fonts 取（改字以后重新运行）；标题栏的 EVO 用面板的 Chakra Petch。都用 PIL 按这台电脑的缩放比例画（`text_image`），不进 Windows 的字体
    - 实测（11-22，源码、100% 缩放）：盖上启动画面要约 55 毫秒（窗口晚出来这么多，主要是读 1024 像素的图标原图）；连续截图看换成网页的那一刻没有空白帧。PictureBox 自带双缓冲，第一次画好之前那块是空的，窗口刚出来会白 30–60 毫秒：第一次画之前先关掉 `AllPaintingInWmPaint`（反射调 `SetStyle`）让它立刻铺底色，画完再开回去，深色时第一帧就是深色了
    - 测试：`tests/test_splash.py`（颜色和尺寸跟 `style.css` 对得上、主题、位置、字体里有那几个字、真的用 WinForms 画一张）
- 托盘：`pystray`（LGPLv3）。右键菜单是 Windows 原生样式，不能自定义颜色。我们的代码是 AGPL-3.0（2026-10-24 起，之前是 MIT）；发布 exe 时要附上 pystray 的许可证原文，并让它以普通 .py 文件的形式放在程序文件夹里（不压进程序内部），方便别人替换
- **Evo 占用**（`code/evo_usage.py`、`process_info.snapshot`，2026-11-15 用户要求；页面上的样子见 `docs/面板.md`"侧边栏下面的「Evo 占用」"）：给玩家看 Evo 自己占多少。游戏帧数不测（用户 11-15 定的：不碰游戏能拿到帧数的只有 ETW / PresentMon，要管理员或"Performance Log Users"组，反作弊怎么看也不清楚）
  - 算法和任务管理器一样（用户决定）：CPU 按整台电脑算（用过的 CPU 时间 ÷（经过的时间 × 逻辑处理器个数），16 线程的电脑上日志里的"15% 个核"在这里约 1%）；内存是"专用工作集"（任务管理器默认显示的那个，11-15 用 `typeperf "\Process(*)\Working Set - Private"` 核对过）。**日志里的"内存"（`process_info.memory_mb`）是工作集**，含和别的程序共用的部分，比这里大（一个空的 Python 约 20 MB 对 10 MB），没改，两种数字不要直接比
  - 怎么量：`NtQuerySystemInformation` 要一份所有进程的列表（CPU 时间、专用工作集、父进程），不打开任何进程（Toolhelp32 也是从这里取的，和看进程名一样不碰游戏）。一次约 5 毫秒（450 个进程）。从托盘进程往下找子进程、孙进程；托盘程序开记录、窗口子进程时 `evo_usage.mark` 记下，它们下面的进程（WebView2）跟着算
  - 现在的：Evo 窗口开着时（每一页右上角都有）每 2 秒问一次 `GET /usage`，和上一次比（`LiveUsage`；隔不到 0.5 秒沿用上一次的、隔了 10 秒以上重新开始）。窗口最小化时不问
  - 对局中的（`MatchMeter`，用户决定记最近 10 局、直接在 main 上做、不改表结构）：记录子进程从认出自己的界面到这一局结束（`in_match.active`）量一段：开始、结束时各要一份进程列表，CPU 相减（中途新开的进程从 0 算，中途关掉的窗口那部分丢了）；内存每 10 秒看一次，取平均和最高；同时记整台电脑的 CPU（`GetSystemTimes`）。这一段之后真的记下了一局（总结页存下，或回到大厅、下一局开局、停止记录时交给 PostMatch 存下）才算，靶场里的、不到 1 分钟的不算。存在数据库旁边的 `usage.json`（最近 10 局，先写临时文件再换过去），日志里每局写一行"这局对局中 Evo 占用：…"
  - 测试：`tests/test_usage.py`
- 托盘程序 `evo_app.py` 的结构：托盘进程只负责检测游戏、托盘图标和面板（约 37 MB）；检测到游戏时另开一个**记录子进程**跑 `live_collect.collect()`，游戏关掉就让它安全停下并退出，识别模型的内存全部还给系统（停下后托盘回到 37 MB）。识别模块崩溃也只影响子进程，60 秒后自动重试
- 启动行为：打开 Evo 就立刻弹出窗口（约 1 秒），不能只在托盘里，否则像没打开成功。Evo 已经在运行时再双击，就让它把窗口弹出来（Windows 命名事件），不弹"已经在运行"的提示。关掉窗口 Evo 仍在托盘里记录，第一次关时弹一条 Windows 通知说明，只提示一次（记在数据文件夹的 `settings.json`）。"只能运行一个"按数据文件夹区分
- 开机自动启动（`code/autostart.py`，0.3.6 起，2026-10-21 用户决定）：注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 里一条 `Evo Tracker` = `"…\Evo.exe" --background`（只影响当前 Windows 用户、不用管理员权限，任务管理器"启动应用"里能关；没用"启动"文件夹的快捷方式）。默认关；第一次打开时页面顶部问一次（在"自动检查新版本"之后），设置页"常规"里有开关。开关的状态不另外记，每次读注册表：在任务管理器里关掉的记在 `...\Explorer\StartupApproved\Run`（第一个字节单数 = 关），显示关；在 Evo 里重新打开时删掉那条。写完读回来核对，没写上（多半是火绒、360 拦住了）提示"没有成功开启自启，请检查是否被杀毒软件拦截"。每次打开 Evo（`autostart.after_start`）：启动项指向的 Evo.exe 不在了（换了程序文件夹）就改成现在这个，指向另一个还在的 Evo 不动；状态写进日志。用源码运行、在临时文件夹里（压缩包里直接双击）不能设置。一键更新程序位置不变，不受影响。`--background` 启动时第一次检查新版本推迟到 2 分钟后（刚开机网络可能还没连上）。测试 `tests/test_autostart.py` 写在 `HKCU\Software\Evo-test`，跑完删掉
- 提示音（`code/sounds.py`，0.3.6 起，2026-10-21 用户决定）：用 Python 自带的 `winsound.PlaySound` 异步播放（不加依赖，内存不变）。对局中的三声由记录子进程放，设置页的"试听"由托盘进程放。声音包（2026-10-24 用户决定：整套切换）：`assets/sounds/<名字>/` 一个文件夹一套（`pack.json` + 三个 16 位 WAV，每段最长 10 秒，缺的那一声用默认的），随安装包发；默认的那套是 `woman`（严肃女声，2026-11-21 用户决定，没选过声音包的老玩家也跟着换；`sounds.DEFAULT_PACK`），之前默认的 `evo` 是自己合成的那套，改名"简洁音效"（`python tools/make_sounds.py` 生成，AGPL-3.0，合计约 370 KB）。"自己的文件"：设置页给每一声选一个音频，窗口（WebView2 自带的解码）先转成 16 位 44.1 kHz 的 WAV 再交给面板，面板核对后存进数据文件夹的 `sounds/custom/`（原来的文件名记在 settings.json）；Evo 不另加解码的依赖。音量（5–100%，设置页的滑块，振幅按音量的平方）：winsound 不能调音量，所以另存一份调小了的副本在数据文件夹的 `sounds/volume/`，设置改了面板先做好，记录程序找不到时自己做；Windows 音量合成器里照样能调。数据文件夹搬家时 `sounds/` 一起搬（`data_move.ITEMS`）。什么时候响见 `docs/对局全流程图.md` 第 8 步。测试时 `tests/fake_game.py` 把 `sounds._output` 换成记一笔，不真的出声

## 打包和安装

  - **在中国大陆上不去**：玩家要自己开着能访问国外网站的工具（系统代理或 TUN）。Evo 不提供代理、**不加任何代理设置**（Python 的 urllib 在 Windows 上本来就跟着系统代理走，WebView2 也是）。连不上（网络层失败）时：取开播状态的那一批结果带 `unreachable`，看直播页名单里写"连不上"、名单上方一行说明、播放器那一块写"啊哦，看起来你不具备看Twitch的“环境”，重试一下吧"和"重试"按钮（点了带 `retry=1` 问开播状态：`live_status.retry_twitch()` 忘掉"连不上"、马上重查）；`/esports/play` 回 `reason: "unreachable"`（不是 `upstream`），`/esports/stream` 的 502 也一样。之后 120 秒以内不再问 Twitch，只在内存里记着，过了再试
  - **旧版本兼容的写法**（2026-11-25）：0.7.2 及以前的 Evo 不认识 `twitch`，会把这样的选手从队伍里整个丢掉。所以公布的文件里 Twitch 的**选手**写成 `{"platform": "none", "room": "", "stream": {"platform": "twitch", "room": "imperialhal__"}, ...}`：旧版本照旧当"不直播"，新版本从 `stream` 里认出来（`esports_data.clean_player`；`stream` 写得不对就忽略它、照旧不直播）。主舞台、主播的 Twitch 直接写 `platform: "twitch"`。`tools/esports.py` 和协作网页的生成器都这样写
  - 2026-11-25 在瑞士真联网试过：查开播（`imperialhal__`、`genburten`）和取地址、读多档目录都通；**国内的网络没试**
